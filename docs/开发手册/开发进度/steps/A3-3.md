### 3.2 验证：gateway.chat() fallback 逻辑

```
打开 gateway.py，逐项核对：

[ ] ENGINE_ORDER = ["deepseek", "doubao", "kimi", "wenxin"]
    — 降级顺序：deepseek 排第一

[ ] _fallback_order(preferred) 算法：
    - 如果 preferred 在 order 里 → 移到最前
    - 如果 LLM_DEFAULT_ENGINE 也在 order 且不是第一 → pass（不改变）

[ ] gateway.chat() 降级行为：
    - for engine in order → get_adapter → 检查 api_key → 调用 chat()
    - 如果 resp.ok → 立即返回（不继续降级）
    - 如果 resp 失败 → 记录 error，继续下一个引擎
    - 全部失败 → last_response.error 合并所有 errors

[ ] 关键边界：
    - get_adapter 返回 None → `errors.append("no adapter")`，continue
    - adapter.api_key 为空 → `errors.append("not configured")`，continue
    - 重试由 adapters._do_request() 的 @retry 装饰器处理（3次，指数退避）
    - gateway 本身不做重试
```

### 3.3 验证：gateway.embed() + 错误处理

```
[ ] embed() 降级顺序同 chat() → 复用 _fallback_order()

[ ] embed 成功判定：r.error is None and any(len(v) for v in r.vectors)
    — 不只是 error is None，还要 vectors 非空

[ ] 与 chat 的不同：
    - embed 不做 retry_count 累加
    - 全部失败返回 vectors=[[] for _ in request.texts]（空向量列表）
```

### 3.4 验证：adapters._OpenAICompatAdapter 重试

```
打开 adapters.py，核对 _do_request()：

[ ] @retry 装饰器：
    - stop=stop_after_attempt(3)         → 最多 3 次
    - wait=wait_exponential(min=0.5, max=6) → 指数退避 0.5→1→2→4s
    - retry=retry_if_exception_type((HTTPStatusError, ConnectError, TimeoutException))

[ ] 重试条件：
    - HTTP 400+ → 抛 HTTPStatusError → 触发重试
    - 连接失败 → ConnectError → 触发重试
    - 超时 → TimeoutException → 触发重试
```
