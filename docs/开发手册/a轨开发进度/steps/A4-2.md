## 3. 改动清单

### 3.1 改动 1：`rag/__init__.py` — 导出 FaissService

**文件**：`backend/app/rag/__init__.py`

**位置**：现有内容替换

**改什么**：从空壳注释改为导出 `FaissService`

```python
"""RAG / Faiss retrieval — KB vector search."""
from app.rag.faiss_service import FaissService  # noqa: F401

__all__ = ["FaissService"]
```

### 3.2 改动 2：`kb_service.py` — `_create` 方法追加 Celery 调用

**文件**：`backend/app/service/kb_service.py`

**位置**：`_BaseKBService._create()` 方法末尾，`return item` 之前（第 115 行附近）

**改什么**：在 `Enterprise.touch_kb(db, enterprise_id)` 之后、`return item` 之前，加一行 Celery 任务调用。**只对 Fact 和 Faq 发任务**（Signal 和 External 不参与向量搜索）。

```python
        # 只有 Fact 和 Faq 需要同步到 Faiss 向量库
        if cls.MODEL in (KBFact, KBFaq):
            from app.tasks.faiss_tasks import faiss_sync_item
            _index_type = "kb_facts" if cls.MODEL is KBFact else "kb_faqs"
            faiss_sync_item.delay(enterprise_id, _index_type, item.id, "create")
```

### 3.3 改动 3：`kb_service.py` — `_update` 方法追加 Celery 调用

**文件**：`backend/app/service/kb_service.py`

**位置**：`_BaseKBService._update()` 方法末尾，`return item` 之前（第 143 行附近）

**改什么**：同 `_create`，加一行 `faiss_sync_item.delay(..., "update")`

```python
        if cls.MODEL in (KBFact, KBFaq):
            from app.tasks.faiss_tasks import faiss_sync_item
            _index_type = "kb_facts" if cls.MODEL is KBFact else "kb_faqs"
            faiss_sync_item.delay(enterprise_id, _index_type, item.id, "update")
```

### 3.4 改动 4：`kb_service.py` — `_delete` 方法追加 Celery 调用

**文件**：`backend/app/service/kb_service.py`

**位置**：`_BaseKBService._delete()` 方法末尾，`Enterprise.touch_kb(db, enterprise_id)` 之后（第 152 行附近）

**改什么**：在 `touch_kb` 之后、方法结束之前，加 Celery 删除任务

```python
        if cls.MODEL in (KBFact, KBFaq):
            from app.tasks.faiss_tasks import faiss_sync_item
            _index_type = "kb_facts" if cls.MODEL is KBFact else "kb_faqs"
            faiss_sync_item.delay(enterprise_id, _index_type, item_id, "delete")
```

## 4. 不可破坏的约束

- ❌ 不改 `_BaseKBService` 的查询/分页/过滤逻辑
- ❌ 不改 SignalService / ExternalService（它们不参与向量搜索）
- ⚠️ Celery worker 未启动时，任务会堆积在 Redis 队列中，不会丢。等 worker 启动后自动消费。
- ⚠️ `faiss_sync_item` 内部做了防御：如果记录已被删除（row is None），会从索引中移除。
