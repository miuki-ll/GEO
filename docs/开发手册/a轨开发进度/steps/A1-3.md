## 3. 验证步骤

### 3.1 注册 + 登录

```bash
# 注册
curl -X POST http://localhost:8000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"test-a1@example.com","password":"Test@12345","full_name":"测试","enterprise_name":"A1测试企业"}'
# 期望: 200, code=0, data.access_token 非空, user.role=owner

# 重复注册同邮箱 → 400 "该邮箱已注册"
# 重复注册同企业名 → 400 "该企业名称已被注册"

# JSON 登录
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test-a1@example.com","password":"Test@12345"}'
# 期望: 200, code=0, data.access_token 非空

# 错误密码 → 401 "邮箱或密码错误"

# /me
curl http://localhost:8000/api/v1/auth/me \
  -H "Authorization: Bearer <token>"
# 期望: 200 + 用户信息（不含 hashed_password）

# /refresh
curl -X POST http://localhost:8000/api/v1/auth/refresh \
  -H "Authorization: Bearer <token>"
# 期望: 200 + 新 TokenPayload
```

### 3.2 JWT 依赖注入链

阅读 `backend/app/core/security.py` 确认链式调用：

```
oauth2_scheme (auto_error=False, 从 Header 取 Bearer token)
  → get_current_user_or_none (decode → 查库 → 返回 User 或 None)
    → get_current_user (None → 401；否则返回 User)
      → require_role(*roles) (角色不在列表 → 403)
```

关键检查点：
- [ ] `oauth2_scheme` 的 `auto_error=False`（公开端点不能自动报 401）
- [ ] `get_current_user_or_none` 覆盖 5 种 None 情况：无 token、decode 失败、type≠access、无 sub、用户不存在/禁用
- [ ] `get_current_user` 在 None 时抛 401
- [ ] `require_role` 角色不匹配时抛 403

### 3.4 target_engines 更新通路

```bash

  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \

```
