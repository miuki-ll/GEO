## 二、并发/异步引擎方案（待用户选择）

**问题**：A7 诊断需要对 25 条探针逐条调 `gateway.search()`，每条 2-3 分钟，串行 = 75 分钟。必须并发。

### 方案 A：asyncio.Semaphore（推荐，简单）

```python
import asyncio

sem = asyncio.Semaphore(3)  # 豆包 QPS≤5，保守设 3 并发

async def search_one(probe):
    async with sem:
        return await gateway.search(SearchRequest(query=probe))

# 25 条探针，3 并发 → ~25/3×3min ≈ 25min
results = await asyncio.gather(*[search_one(p) for p in probes])
```

| 优点 | 缺点 |
|------|------|
| 代码简单，FastAPI 原生支持 | 受限于单进程 |
| 不引入新依赖 | QPS 超限会 429 |

### 方案 B：Celery 任务队列（适合大规模）

```python
@celery.task
def search_probe(probe, enterprise_id):
    return gateway.search_sync(probe)  # 同步版本

# 25 条探针 → 25 个 Celery task → worker 池执行
task_ids = [search_probe.delay(p, eid) for p in probes]
```

| 优点 | 缺点 |
|------|------|
| 可横向扩展 worker | 需要 Redis + Celery 基础设施 |
| 自带重试/超时/结果存储 | 代码复杂度高 |
| 适合 B6 持续监测 | 25 条探针有点小题大做 |

### 方案 C：BackgroundTasks + 轮询（折中）

```python
# POST /diagnosis/all → AgentTask(pending)
# 后台逐条搜索，每完成一条 → update_progress
# SSE 推送实时进度
```

| 优点 | 缺点 |
|------|------|
| 已有 AgentTask + SSE 基础设施 | 串行慢 |
| 用户侧有进度反馈 | 可以改成内部分批并发 |

### 建议

**MVP 用方案 A**（asyncio.Semaphore(3) 并发），未来 B6 持续监测时切方案 B。A5 入驻那边已经有 AgentTask + SSE 骨架，可以直接复用做进度推送。

## 三、持久化方式方案（待用户选择）

**问题**：联网搜索返回的 citations（每条 1200+字 summary）+ answer + 分析结果，存哪里？

### 方案 A：直接存 `source_diagnoses.payload` JSON（推荐，简单）

```json
// source_diagnoses 表，payload 字段（JSON 列）
{
  "query": "静安寺皮肤管理推荐",
  "engine": "doubao",
  "answer": "回答全文...",
  "citations": [
    {"title": "...", "url": "...", "summary": "1200字...", "site_name": "..."},
    ...
  ],
  "brand_mentioned": true,
  "rank": 3,
  "competitor_mentions": ["XX连锁"],
  "simulated": false
}
```

| 优点 | 缺点 |
|------|------|
| 不改表结构，直接用已有的 `source_diagnoses` 表 | payload 会很大（25条探针×9条引用=225条citation） |
| MySQL JSON 列支持索引和查询 | 无法按 citation 维度独立查询 |

### 方案 B：新建 `search_results` 表（正规，灵活）

```python
class SearchResult(Base, TenantMixin, TimestampMixin):
    __tablename__ = "search_results"
    id = Column(Integer, primary_key=True)
    diagnosis_id = Column(Integer, ForeignKey("source_diagnoses.id"))
    engine = Column(String(50))
    query = Column(Text)
    answer = Column(Text)
    citations = Column(JSON)          # [{title, url, summary, site_name}]
    brand_mentioned = Column(Boolean)
    rank = Column(Integer)
    competitor_mentions = Column(JSON)
    simulated = Column(Boolean, default=False)
```

| 优点 | 缺点 |
|------|------|
| 数据结构清晰，方便查询统计 | 需要新建表 + migration |
| 适合 B6 持续监测（每次搜独立记录） | |

### 建议

**MVP 用方案 A**（payload JSON），等 B6 监测需要按 citation 维度查询时再迁移到方案 B。25 条探针的 payload 不会超过 MySQL JSON 列限制（1GB）。
