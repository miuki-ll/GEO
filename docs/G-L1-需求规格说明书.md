## 1. 产品锚点

### 1.1 第一性原理

> 面向**特定目标人群**，匹配**真实问答场景**，输出**信息增量**与**差异化价值**，建立**品牌专业信任**，完成**咨询与成交转化**。

**价值公式：** 内容价值 ≈ 信息增量 × 品牌信任度
**North Star：** AI 信任资产 → 分渠道可见度 → 可验证转化（非软文铺量工厂）

### 1.2 产品定义

**GEO（Generative Engine Optimization，生成式引擎优化）** = 让豆包/DeepSeek/Kimi/文心等 AI 在回答用户问题时，能**引用、采信**企业真实品牌信息。

| 维度 | 说明 |
|------|------|
| 产品形态 | 多租户 GEO SaaS（Web 为主，微信小程序 V2） |
| MVP 行业 | 生美垂直包 `beauty_local`（生活美容/皮肤管理） |
| 差异化 | KB 零幻觉 · LLM 动态生成 · 信源地图 · 监测→修复闭环 · 品类剧本 |
| 不是什么 | 软文工厂、保证排名第一、虚构品牌、刷好评、关键词堆砌、全网爬虫 |

### 1.3 行业包设计原则

**行业包 = 规则簿 + few-shot 提示，不是内容种子库。**

- 硬配（人手维护）：禁词/合规/渠道权重/竞品类型/CTA映射/优先验证项
- 软配（few-shot）：画像提示/探针示例/scenario 示例（仅 3-5 条给 LLM 参考）
- 动态生成（LLM 实时产出）：探针问句/客户画像/词库/scenario/竞品拆解 → 租户天然隔离

### 1.4 明确不做（全版本边界）

| 不做 | 原因 |
|------|------|
| 保证 AI 排名第一 | 不可控、易误导客户 |
| 刷好评 / 虚构品牌 | 合规与品牌风险 |
| 完整 CMS | MVP 仅托管页 + 渠道适配 |
| Neo4j 知识图谱 | PG + Faiss 足够 |
| 全网爬虫 | 仅白名单 page_fetch（用户提交 URL） |
| 蒸馏价格/NAP/参数 | 这些数据必须从 KB 取 |
| 正文 Skill 用 ReAct | 固定链 kb_fetch → LLM → fact_verify |

## 2. 目标用户与核心场景

### 2.1 用户画像（MVP · 生美）

| 角色 | 典型身份 | 核心诉求 |
|------|----------|----------|
| **Owner（店主）** | 美容院/皮肤管理店老板，1-3 家店 | 顾客问 AI 时能被提到；发出的文案敢用、不违规 |
| **Admin（管理员）** | 运营负责人 | 建库、确认方案、发布、看效果 |
| **Editor（编辑）** | 文案/助理 | 改稿、处理机审告警 |
| **Viewer（查看者）** | 投资人/合伙人 | 只看报告，不可改 |

### 2.2 典型场景（User Story）

| ID | 作为… | 我想… | 以便… |
|----|-------|-------|-------|
| US-01 | 店主 | 一次填完店信息、选主攻 AI、点「开始分析」 | 系统自动跑诊断、不用逐步点 |
| US-02 | 店主 | 在一页方案包里看 AI 诊断结果、勾选 2-3 个顾客真实问题 | 只写对转化有用、有 KB 依据的内容 |
| US-03 | 店主 | 审一遍系统生成的 FAQ/小红书稿（策略+草稿合并） | 一次确认、事实无误再发布 |
| US-04 | 店主 | 在效果舱看 AI 是否提到我、24h 后跟基线对比 | 知道钱花在哪、要不要调整 |
| US-05 | 运营 | KB 改价/改项目后收到提示 | 不会静默用旧策略写错价 |
| US-06 | 运营 | 监测 2 周提及率过低时收到策略建议草案 | 人确认后再改方向，系统不自动改 |
| US-07 | 店主 | 在设置页修改主攻 AI | 下次诊断和监测自动切换引擎 |

### 2.3 行业扩展路线

| 版本 | 行业 | 说明 |
|------|------|------|
| MVP | `beauty_local` | 本地生活、高 FAQ 需求、合规敏感 |
| V1 | + 餐饮 / 维修 / 零售 | 本地生活全品类 |
| V2 | `b2b_manufacturing` | 深度内容、选型指南、采购链 persona |

## 3. 闭环与三舱

### 3.1 闭环七段

```
录入 KB → 信源诊断 → 定 scenario → 生产+双审 → 分渠道发布 → AI 监测 → 转化反馈/迭代草案
         ↑________________补 KB / 改 scenario________________|  ↑____策略草案（人确认）____|
```

| 阶段 | 三舱 | 人闸门 |
|------|------|--------|
| 录入+诊断+词库 | 舱1 懂我 | — |
| 策略+生产+检测 | 舱2 定方案 | **人闸门（策略+草稿合并一次确认）** |
| 发布+监测+迭代 | 舱3 出结果 | 策略草案确认 |

### 3.2 三舱对照

| 舱 | 用户说 | 系统后台 |
|----|--------|----------|
| **舱1 懂我** | 告诉店的信息、选 AI、看诊断 | 建库 → LLM生成探针 → 5项诊断 → 四源汇聚词库 → 画像 → 竞品 |
| **舱2 定方案** | 看方案包、勾选 scenario、审草稿 | LLM 生成画像+scenario → 渠道权重混合 → 内容工厂 → RAG切片 → 5项检测 → 人闸门 |
| **舱3 出结果** | 发布、看效果 | 发布 AUTO/SEMI/GUIDED → T0/T1 对比 → 四层漏斗 → 转化闭环 → 迭代入口 |

### 3.3 对外 3 步

**Step 1 · 开店向导** — 一次提交：选主攻 AI + 品类 + 店信息 + 目标客户 + 竞品 + 核心优势 + RawInputs → `[开始分析]` → 后台 4 节点 job 链（进度条）。

**Step 2 · 方案包 + 草稿审** — 方案包五区（LLM 生成画像/竞品/scenario）→ 勾选 scenario → `[确认并生成草稿]` → 草稿列表 → 策略+草稿合并 `[确认并发布]`

**Step 3 · 效果舱** — 发布 + Dashboard（AI KPI + T0/T1 对比 + 四层漏斗 + 转化闭环；V1.1 + 咨询归因）。

**铁律：** 无 Fact 不发布；条数 = 已选 scenario 数（≤5 首次）；临界只出草案、人确认后迭代。

## 4. 系统管道（8 步功能规格）

### 4.1 管道总览

```
1.入驻 → 2.诊断agent → 3.意图词库 → 4.策略生成
  → 5.内容工厂 → 6.内容检测 → 🔴人闸门 → 7.发布 → 8.监控迭代
```

---

### 4.2 步骤 1 · 入驻建库（FR-ON）

| 编号 | 需求 | 优先级 |
|------|------|:--:|
| FR-ON-01 | 开店向导 6 步填表：选主攻 AI、品牌/门店 NAP、项目/服务（含价格区间）、目标客户（模板多选）、竞品（店名+可选 URL）、核心优势 | P0 |
| FR-ON-02 | RawInputs 录入：支持文本粘贴（客服聊天/评价/销售话术），进 KB Signal | P0 |
| FR-ON-03 | 选品类后激活对应行业包规则簿（禁词/合规/渠道默认/CTA），注入租户配置 | P0 |
| FR-ON-04 | 主攻 AI 必选 ≥1 个 engine，存入 `target_engines[]`，后续诊断和监测以此为范围 | P0 |
| FR-ON-05 | 提交时自动生成：品牌标准实体库（Fact 从用户填写直接写入）、托管页（含 Schema LocalBusiness + FAQPage + llms.txt） | P0 |
| FR-ON-06 | 主攻 AI 可在设置页随时修改，修改后诊断和监测的 EngineAdapter 联动切换 | P1 |

### 4.3 步骤 2 · 诊断 agent（FR-DG）

| 编号 | 需求 | 优先级 |
|------|------|:--:|
| FR-DG-01 | **探针问句 LLM 动态生成**：输入品类+商圈+店名+服务项目+价格带+核心优势+行业包 probe_few_shot，LLM 输出 20-30 条自然问句覆盖四层意图 | P0 |
| FR-DG-02 | EngineAdapter 在用户选择的 target_engines 上逐条测试，采集 4 项指标：品牌提及率、推荐顺位、信息失真度、竞品挤占度 | P0 |
| FR-DG-03 | **实体健康度检测**：AI 知识图谱内品牌实体完整度、关联词条密度、权威信源数量 | P0 |
| FR-DG-04 | **信源地图**：探针→采集「思考资料/参考资料」URL→域名聚合→生成《平台信源排行榜》+ 优先投放渠道清单 + 信源覆盖缺口报告 | P0 |
| FR-DG-05 | **三类赛道判定**：空白赛道（无标准答案，优先布局）、突围赛道（竞品信息单薄，快速反超）、防御赛道（竞品长期霸榜，权威背书+细分场景） | P0 |
| FR-DG-06 | **竞品逆向拆解 LLM 生成**：行业包只给 competitor_types（分类名），LLM 根据用户提交竞品名+URL+AI对比探测结果，生成竞品实体图谱/可信度向量/漏洞捕捉 | P0 |
| FR-DG-07 | 输出《GEO 健康报告》含三段话术：空白赛道（紧迫感）、突围赛道（机会感）、防御赛道（损失感） | P0 |
| FR-DG-08 | 诊断默认仅主攻 engine 全量；次攻可配置降频/跳过（控制 LLM 成本） | P0 |
| FR-DG-09 | 探针 T0 = 入驻时采集（基线），T1 = 发布 24h 后采集（效果对比），两次结果进步骤8 对比展示 | P0 |

### 4.10 步骤 8 · 监控迭代（FR-MN）

## 6. 用户核心流程

### 6.1 新用户完整链路

```
Step 1 · 舱1 懂我
  入驻填店信息 + 选主攻 AI + 品类 → 点击[开始分析]
  → LLM 生成探针（probe_few_shot引导）
  → 诊断 agent 自动跑 5 项（信源地图/赛道/竞品LLM拆解）
  → 四层词库确认（四源汇聚+LLM提炼+用户编辑）→ 跳转方案包

Step 2 · 舱2 定方案
  方案包五区（画像LLM生成 · scenarioLLM生成 · 渠道混合权重）
  → 用户勾选 scenario → [确认并生成草稿]
  → 内容工厂（RAG切片·步骤5）→ 内容检测（5项·含RAG验证·步骤6）
  → 策略+草稿合并人闸门 → [确认并发布]

Step 3 · 舱3 出结果
  发布 agent 自动发布 → 24h 后 T1 vs T0 对比
  → 监控 agent 持续运行（EngineAdapter 联动 target_engines）
  → 效果舱 Dashboard（四层漏斗 + 转化闭环）
  → 临界触发 → 策略草案 → 人确认 → 迭代
```

### 6.2 异常流程

| 场景 | 处理 |
|------|------|
| thin KB（知识库为空） | 方案包黄条提示「先补项目+FAQ」，不硬生成空文 |
| fact_verify 不通过 | 草稿标红 + 告警类型，打回步骤5 |
| 小红书 AUTO 失败 | 自动降级 SEMI 导出包 |
| engine 联网 API 超时/限流 | 重试 1 次，失败 skip，不阻断 pipeline |
| 探针结果全部未提及 | 触发 gap_analyze → 策略更新草案 |
| 用户修改主攻 AI | target_engines 更新 → 下次诊断/监测自动切换 |

## 9. 验收标准（AC-01 ~ AC-15）

### 9.1 MVP-A 最小路径

```
生美 1 店
  → 入驻（选主攻 AI + 填 NAP + 项目 + 竞品 + RawInputs）
  → 诊断（探针 LLM 生成 · 5项全量 · 含信源地图 · 竞品 LLM 拆解）
  → 四层词库（四源汇聚 · 租户隔离 · 用户确认编辑）
  → 方案包（persona LLM 生成 + scenario LLM 生成 + 渠道混合权重）
  → 内容工厂（scenario 模式 · RAG 切片 · 步骤5）
  → 内容检测（5 项 · 含 RAG 可检索性验证 · 步骤6）
  → 人闸门（策略+草稿合并）
  → 发布（托管页 AUTO + 小红书 SEMI）
  → 监控（24h 后 T1 vs T0 · EngineAdapter 联动）
  → 效果舱（四层漏斗 + 转化闭环）
```

### 9.2 核心验收项

| # | 验收项 | 判定标准 |
|---|--------|----------|
| AC-01 | 8 步流程跑通 | 入驻→诊断→词库→方案包→内容→检测→人闸门→发布→监控 |
| AC-02 | fact_refs 可追溯 | 生成内容中参数/价格可定位到 kb_facts.id |
| AC-03 | 禁词拦截 | 行业包 forbidden_words + 广告法禁词拒发；含 AI 生成标识 |
| AC-04 | 探针 LLM 生成 | 根据品类+商圈+店名动态生成 20-30 条问句，非模板 |
| AC-05 | 四层词库租户隔离 | 不同租户词库完全不同，四源汇聚可追溯 |
| AC-06 | persona LLM 生成 | 从 RawInputs+探针实时分析，非行业包种子 |
| AC-07 | scenario LLM 生成 | 8-10 条候选，从词库+画像+竞品提炼，用户勾选 |
| AC-08 | 渠道权重混合模型 | 内部固定 0.6 + 探针实测 0.4 |
| AC-09 | RAG 切片 | 生成时切（步骤5）+ 检测时验证（步骤6） |
| AC-10 | 5 项机审 | fact_verify + 禁词 + 交叉验证 + 实体一致性 + RAG可检索性 |
| AC-11 | 人闸门合并 | 策略+草稿一次确认，approval_log 有记录 |
| AC-12 | 探针两次对比 | T0（基线）+ T1（24h 后）Δ 展示 |
| AC-13 | 主攻 AI 联动切换 | 用户改 target_engines → 监测 EngineAdapter 跟随变化 |
| AC-14 | 租户隔离 | 跨 enterprise API 403 |
| AC-15 | 行业包薄配置 | 新增品类只需配 9 项规则 + few-shot，0 管道改动 |
