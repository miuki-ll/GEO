# v4 需求多角色评估与优化建议

> **日期**：2026-07-04 | **状态**：**v4.1 已吸收可落地项** → 见各文档；**暂未落地** → [`二期.md`](./二期.md)

---

## 总览

| 维度 | 评分 | 一句话 |
|------|:----:|--------|
| 产品 | 4.2 | 战略清晰、闭环补齐；MVP 仍偏大，指标口径未完全统一 |
| 视觉/UX | 3.3 | 三舱结构好，缺线框与信息层级 |
| 技术 | 4.0 | 架构成熟；实现面宽，成本与依赖未量化 |

**综合**：v4 已从「功能堆叠」升级为「产品系统」，可开干；上线前先 **砍 MVP** + **补 4 张线框**。

---

## 1. 产品

**优点**：锚点一致；闭环七段；scenario-first 纠正铺量；边界清晰（不保证第一、Agent 只出草案）；FR/AC 可追溯。

**缺口**

| 问题 | 建议 |
|------|------|
| MVP 像小 V1.0（4 引擎+LangGraph+多渠道） | 定义 **MVP-A**：单引擎诊断 + 2 scenario + 托管页 + 1 渠道 SEMI |
| Core 用词库、叙事用 scenario（O-06） | MVP 将 **已选 scenario 同步进 Core 子集** |
| North Star 难量化 | 补 3 指标：Core 提及率、托管页表单数、单店闭环天数 |
| thin KB 仅黄条不阻断 | 无 ≥3 FAQ 或 ≥2 项目 → 灰掉「确认并生成」 |
| 计费细则未定（O-03） | 标准包 = 3 scenario + 2 引擎监测，加购按 scenario |

---

## 2. 视觉 / UX

**优点**：三舱隐喻清晰；2 次闸门简单；方案包 A～E 有架构；E 区折叠词库合理。

**缺口**

| 问题 | 建议 |
|------|------|
| 方案包单页过密 | 默认只展示 A+C+主按钮；B/D「展开高级」 |
| 分析等待 ~15min | 分步叙事 + 预计剩余时间 + 失败重试 |
| 无草稿审 UI 规格 | 三栏：预览 \| fact_refs 来源 \| 告警处理 |
| Element Plus 偏后台 | 大字号结论、卡片化；效果舱偏「报告感」 |
| 无线框 | 优先 4 张：开店向导、方案包、草稿审、效果舱 |

---

## 3. 技术

**优点**：kb_fetch 主链；Agent 分层清楚；Pydantic v2；LangSmith+agent_traces 双写；SEMI 降级务实。

**缺口**

| 问题 | 建议 |
|------|------|
| LLM 成本未估 | 单租户月成本模型；诊断默认仅主攻引擎 |
| SEO API 未定（O-02） | MVP 用 RawInputs+diagnose 反推，SEO API 降 P1 |
| Faiss per-tenant | OSS 备份 + tenant 删除级联 |
| XHS/知乎 AUTO 复杂 | MVP **SEMI 为主**，AUTO 为尝试 |
| jobs + LangGraph 双编排 | job_id 贯穿 checkpoint，单一真相源 |
| 缺 DR/限流 | 补 RDS 备份、tenant rate limit、LLM 配额熔断 |

---

## 4. 运营

**优点**：Core/Probe 分离；临界只出草案；SEMI/GUIDED 务实；老板版可售前。

**缺口**

| 问题 | 建议 |
|------|------|
| MVP 无 ConsultLog，闭环断一半 | 售前强调「可见度+店页表单」，V1.1 再讲归因 |
| 无录入 SOP | checklist：NAP、≥5 条聊天、2 竞品 |
| SEMI 包未定义 | 标准包：标题+正文+标签+封面建议+发布步骤 |
| 4～8 周见效 | 效果舱加「第 N 周 / 建议动作」时间线 |
| 监测配额未落地 | 与计费同步，如 2 引擎 × 20 Core prompt/月 |

---

## 5. 安全 / 合规

**优点**：fact_verify+生美禁词+AI 标识；ReAct 禁 write_fact/publish；租户隔离；凭证 AES；LangSmith 无 PII。

**缺口**

| 问题 | 建议 |
|------|------|
| RawInputs 含顾客 PII | 数据分级、保留期、录入脱敏提示 |
| 数据发 4 家 LLM | 用户协议+数据处理附录；可选「仅国内模型」 |
| page_fetch 法律风险 | 仅用户提交 URL；日志留痕 |
| 无人工审 audit | content_asset 加 approval_log（user_id, diff, ts） |
| 托管页 XSS | 发布前 sanitize + CSP |
| 无安全 AC | 增 AC-SEC-01：跨 tenant 访问必 403 |

---

## 优先补 5 件（跨角色共识）

1. **MVP 真范围表** — 产品+技术：FR 从 P0 降到 P0.5/P1 的清单  
2. **4 张核心线框** — 视觉：向导 / 方案包 / 草稿审 / 效果舱  
3. **thin KB 硬门槛** — 产品+运营：薄库禁止批量生成  
4. **Core 与 scenario 最小对齐** — 已选 scenario 进 Core 子集  
5. **隐私 + 审批审计** — RawInputs 告知、approval_log、SEMI SOP
