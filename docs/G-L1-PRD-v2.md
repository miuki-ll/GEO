## 0. 设计原则（T-GEO 五层架构）

产品模块按迈富时 T-GEO 五层认知架构组织。用户界面用三舱包装，后台管道用五层驱动。

```
五层（后端架构）              三舱（前端界面）           用户看到的
─────────────               ─────────────             ──────────
实体层 → 品牌知识底座          舱1 懂我                  填信息、看诊断
语义层 → 知识图谱关联          舱1 懂我                  四层词库、画像
检索层 → RAG切片适配           舱2 定方案                 方案包、草稿
生成层 → 3C内容引导            舱2 定方案                 内容工厂
校验层 → 幻觉拦截+巡检         舱3 出结果                 监测、迭代
```

### 0.1 行业包设计原则

**行业包 = 规则簿 + few-shot 提示，不是内容种子库。**

```
硬配（人手维护 · 品类间不可复用）：
  forbidden_words / compliance_checklist / channel_defaults
  competitor_types / cta_mapping / priority_verification
  persona_hint / probe_few_shot / scenario_few_shot

动态生成（LLM 实时产出 · 租户天然隔离）：
  probe_prompts / persona_profiles / keyword_library
  scenarios / competitor_profiles / differentiation_brief / content_gaps
```

每个租户的商圈、店名、RawInputs、探针结果完全不同，LLM 产出也完全不同——**行业包从「内容种子库」变为「规则簿 + LLM 提示指南」**。

## 1. 产品定位

### 1.1 一句话

让周边生活小店在 **7–14 天**内完成「AI 能搜到 → 信息正确 → 客户找得到 → 能成交」的 GEO 闭环。

### 1.2 核心痛点

| 层次 | 痛点 | 表现 |
|------|------|------|
| **AI 失声** | 用户在豆包/DeepSeek/Kimi 搜「附近 XX 哪家好」，AI 提不到你的店 | 品牌提及率 < 5% |
| **信息幻觉** | 提到了但电话/地址/营业时间是错的 | 客户流失，转化归零 |
| **有曝光无转化** | 被推荐了但没有导航/电话/预约入口 | 看了白看 |

### 1.3 不是什么

| ❌ 不做 | 原因 |
|---------|------|
| 软文工厂 | 不按篇数 KPI 驱动，首次 scenario 模式 ≤5 条 |
| 保证 AI 排名第一 | 大模型引用概率行为，不卖虚假承诺 |
| 虚构品牌 / 刷好评 | fact_verify + 禁词拦截 + 人工审核三道防线 |
| 堆关键词 / SEO 老路 | AI 看结构化信息 + 跨平台交叉验证，不是关键词密度 |

### 1.4 差异化（USP）

| USP | 竞品怎么做 | 我们怎么做 |
|-----|-----------|-----------|
| **品类剧本** | 一套模板打天下 | 行业包 = 规则簿，内容全由 LLM 动态生成、租户隔离 |
| **信源地图** | 不告诉你要发哪里 | 探针 → 采集 URL → 域名聚合 → 排行榜 → 渠道计划 |
| **监测→修复闭环** | 告诉你病了不给药 | 监测 → 诊断 → 生成修复内容 → 复测验证 |
| **零幻觉铁律** | 铺量工具不管事实 | 无 Fact 不发布，fact_verify + 禁词 + 交叉验证 + 实体一致性 |
| **小店自助** | 大厂要驻场、小工具只有半截 | 开店向导 → 方案包确认 → 效果舱，3 步完成 |
| **LBS 本地化** | 不做或弱做 | 商圈/地铁口/小区变量绑定，品类分流转化 |
| **主攻 AI 用户自选** | 写死或不管 | 入驻时选择，随时可改，监测 EngineAdapter 联动切换 |

## 2. 目标用户

### 2.1 用户画像（MVP · 生美行业）

| 角色 | 身份 | 核心诉求 |
|------|------|----------|
| **Owner（店主）** | 美容院/皮肤管理店老板，1-3 家店 | 顾客问 AI 时能被提到；发出的文案敢用、不违规 |
| **Admin（管理员）** | 运营负责人 | 建库、确认方案、发布、看效果 |
| **Editor（编辑）** | 文案/助理 | 改稿、处理机审告警 |
| **Viewer（查看者）** | 投资人/合伙人 | 只看报告，不可改 |

### 2.2 行业扩展路线

```
MVP（当前）  →  V1        →  V2
beauty_local   本地生活全品类   B2B 制造/工业
（生美）       +餐饮+维修+零售 （选型指南·深度内容）
```

### 2.3 跨品类适用性

8 步管道和三舱 UX 完全品类无关。切换品类只需替换行业包规则簿（禁词/合规/CTA/竞品类型），所有内容（探针/词库/画像/scenario）由 LLM 根据新品类规则动态生成。详见 [§3.2 行业包结构](#32-行业包结构瘦身规则簿)。

### 3.2 行业包结构（瘦身规则簿）

**所有动态生成的数据，行业包不提供种子。行业包只提供不可变的规则 + 给 LLM 的 few-shot 提示。**

```yaml
# 瘦身后的行业包（以 beauty_local 为例）
industry_pack:
  name: "beauty_local"
  display_name: "生活美容"

  # ========== 硬配：规则（人手维护 · 品类间不可复用）==========

  forbidden_words:                    # 禁词
    - "根治" "永不复发" "100%治愈" "国家级" "第一"
  banned_patterns:                    # 禁词正则
    - "祛斑\\d+%" "美白根治"

  compliance_checklist:               # 合规检查
    - id: medical_words
      severity: high
      description: "医疗功效禁用词"
    - id: qualification_clarity
      severity: high
      description: "必须声明卫生许可证与营业执照"

  channel_defaults:                   # 默认渠道权重
    - { name: "AI托管页", weight: 40, mode: "auto" }
    - { name: "小红书", weight: 25, mode: "semi" }
    - { name: "知乎", weight: 10, mode: "semi" }
    - { name: "大众点评", weight: 15, mode: "guided" }
    - { name: "抖音", weight: 10, mode: "guided" }

  competitor_types:                   # 竞品类型（仅分类名，不填具体内容）
    - { type: "chain", label: "区域连锁品牌店" }
    - { type: "local", label: "社区单店" }
    - { type: "studio", label: "私人工坊" }

  cta_mapping:                        # 品类 CTA
    answer_goal: "风格标签 + 案例 + 评价"
    landing: "预约小程序 / 企微 / 作品集页"
    no_phone_push: true               # 不强行推电话

  priority_verification: "案例/评价/风格标签（不强行推电话）"

  # ========== 软配：few-shot prompt（给 LLM 参考，不是种子数据）==========

  persona_hint:                       # 画像生成方向（给 LLM 的提示）
    age_range: [25, 45]
    genders: ["女性"]
    typical_decision_factors: ["口碑", "资质", "距离", "价格", "风格标签", "人员手法"]
    typical_needs: ["补水", "抗衰", "敏感肌修护", "祛痘", "美白淡斑"]

  probe_few_shot:                     # 探针问句 few-shot（3-5 条示例）
    - "XX区做敏感肌修护推荐哪家美容院？"
    - "换季泛红美容院做什么项目？"
    - "XX路附近的皮肤管理中心推荐"

  scenario_few_shot:                  # scenario few-shot（3-5 条示例）
    - "敏感肌能不能做皮肤管理"
    - "夏天油皮补水做什么项目比较好"
    - "痘痘肌适合做什么护理"

  # ========== 全部动态生成（行业包不提供）==========
  # probe_prompts        → 步骤2 LLM 根据品类+商圈+店名实时生成
  # persona_profiles     → 步骤4 LLM 分析 RawInputs+探针结果 实时生成
  # keyword_library      → 步骤3 四源汇聚（RawInputs+探针+SEO+LLM）
  # scenarios            → 步骤4 LLM 从词库+画像+竞品 实时提炼
  # competitor_profiles  → 步骤2 LLM 对用户提交的竞品做深度拆解
  # differentiation_brief → 步骤4 基于拆解结果生成差异简报
  # content_gaps         → 步骤4 对比诊断结果和已有内容，生成缺口清单
```

### 3.3 步骤详解

---

#### 步骤1 · 入驻建库（舱1）

```
用户填写：
  ├─ 选主攻 AI（豆包/DeepSeek/Kimi/文心/抖音AI）★ 用户自选，非行业包写死
  ├─ 品类选择 → 激活对应行业包规则簿（禁词/合规/渠道/CTA）
  ├─ 品牌/门店 NAP（店名/地址/电话/营业时间/经纬度）
  ├─ 项目/服务（名称/价格区间/时长/适用人群）
  ├─ 目标客户（模板多选 → persona 种子提示）
  ├─ 竞品（店名 + 可选 URL）
  ├─ 核心优势（一句话 → brand.differentiator）
  └─ RawInputs（客服聊天/评价/销售话术等原始素材）

主攻 AI 选择规则：
  - 入驻时必选 ≥1 个主攻 engine
  - 决定步骤2 探针测试范围 + 步骤8 监测范围
  - 保存到 target_engines[]
  - 用户随时可在设置中修改 → 修改后诊断和监测的 EngineAdapter 联动切换
  - 次攻 engine 可选，系统默认降频/跳过以控制成本

系统后台（入驻提交时自动跑）：
  ├─ 品牌标准实体库（Fact 从用户填写直接写入，不靠行业包种子模板）
  ├─ 托管页（含 Schema.org LocalBusiness + FAQPage + llms.txt）
  └─ 行业包规则簿激活（禁词/合规/渠道默认值加载到租户配置）

产出物：
  - KB：Enterprise/Brand/Stores/Services/KBFact/KBFaq/KBSignal
  - 托管页 URL（Schema 已部署）
  - llms.txt（根目录：店名/服务/价格/联系方式/FAQ链接）
  - 租户级 target_engines[]（后续诊断和监测均以此为范围）
```

#### 步骤2 · 诊断 agent（舱1）

**全量 5 项。所有内容由 LLM 动态生成，行业包只给规则和 few-shot。**

**返回给客户的内容策略：「制造焦虑 + 制造需求」。**

```
诊断 agent 自动跑：

┌─ ① 四大指标（探针批量测试）
│
│   探针问句生成（LLM 动态生成，不是行业包手写模板）：
│     输入 → LLM：
│       1. 商家填的：品类、商圈、店名、服务项目、价格带、核心优势
│       2. 行业包的：probe_few_shot（3-5 条示例）+ priority_verification
│       3. 目标：生成 20-30 条自然问句，覆盖四层意图
│     输出 → probe_prompts[]：
│       选型层：「静安寺附近有什么好的皮肤管理」「XX路美容院推荐」
│       场景层：「静安寺适合敏感肌的美容院」「换季泛红去哪做」
│       痛点层：「XX路皮肤管理哪家不推销」「做脸会不会越做越敏感」
│       认知层：「皮肤管理和医美有什么区别」「敏感肌多久做一次护理」
│
│   然后 → EngineAdapter 在用户选的主攻 AI 上逐条提问 → 采集结果
│     品牌提及率 — AI答案中是否出现品牌
│     推荐顺位   — 是否放在Top3推荐清单
│     信息失真度 — 电话/地址/营业时间是否存在幻觉
│     竞品挤占度 — 同问题下竞品曝光频次
│
├─ ② 实体健康度检测
│   AI知识图谱内品牌实体完整度
│   关联词条密度 / 权威信源数量
│
├─ ③ 信源地图（核心差异化）
│   探针问句 → 各平台提问 → 采集「思考资料/参考资料」URL
│   → 域名聚合统计 → 生成该商家专属《平台信源排行榜》
│   → 输出：优先投放渠道清单 + 信源覆盖缺口报告
│   复测：第3/7/15天信源变化追踪
│
├─ ④ 三类赛道判定
│   空白赛道 → 无标准答案，优先布局
│   突围赛道 → 竞品信息单薄，快速反超
│   防御赛道 → 竞品长期霸榜，权威背书+细分场景
│
└─ ⑤ 竞品逆向拆解（LLM 动态生成）
     竞品类型 → 行业包 competitor_types（仅分类名，如「区域连锁品牌店」）
     具体画像 → LLM 根据用户提交的竞品名+URL+AI对比探测结果，填入具体信息
       - 竞品实体图谱：该竞品布局了哪些平台/内容
       - 竞品可信度向量：权威媒体/第三方报告/案例数量
       - 内容结构复刻+升级：竞品高收录框架+数据案例降维打击
       - 漏洞捕捉：信息缺失/参数错误/无细分场景 → 优先填充

产出物：GEO 健康报告（含制造焦虑话术）

探针采集时机：
  T0 = 入驻时（基线）
  T1 = 发布 24h 后（效果对比）→ 进步骤8 监控
```

#### 步骤3 · 本地意图词库（舱1）

**独立步骤。四源汇聚、LLM 提炼、完全租户隔离。行业包不提供种子词。**

```
四源汇聚：

  来源1 · RawInputs（客户上传）
    客服聊天记录/评价/销售话术
    → exact 去重 → embedding → Faiss per-tenant 聚类(≥0.85) → LLM 簇命名
    → 归入四层（认知/选型/痛点/场景）

  来源2 · 探针反推（步骤2 诊断 agent）
    探针问句跑完后，AI Chat 的回答里提取高频词/品类词/场景词
    → 归入四层

  来源3 · SEO/问答 API
    5118 / 百度指数 / 知乎热榜
    → 该品类+商圈的本地热搜词 → 归入四层

  来源4 · LLM 直接生成
    输入：品类+商圈+服务项目+探针结果
    → LLM：「根据以上信息，生成该店的四层意图词库」
    → 每层输出 10-15 条

  → 四源合并 → 去重 → 四层结构草案 → 用户确认/编辑

四层词库结构：
  认知层 → XX是什么、XX原理、行业标准        ← 填语义网
  选型层 → {商圈}XX推荐、XX哪家好、性价比    ← 核心转化词 · 70% 资源
  痛点层 → XX避坑、XX贵吗、XX营业时间        ← 需求词
  场景层 → 情侣约会、带娃、加班宵夜、公司团建  ← 细分流量 · 70% 资源

LBS 变量绑定：{商圈} {地铁口} {小区} {行政区}

产出物：
  - 确认后的四层词库（进 KeywordLibrary · 租户隔离 · 监测 Core 池槽位）
  - 高频问句 → 标准化 FAQ draft
  - 每词标注来源（RawInputs / 探针反推 / SEO API / LLM生成 / 手动）

用户操作：
  列表展示四层，每层可增删改
  每词标注来源
```

#### 步骤4 · 策略生成（舱2）

**输入全部来自前面步骤的动态产出。画像和 scenario 由 LLM 生成，行业包只给 few-shot。**

```
输入：
  ├─ 诊断报告（步骤2 全部 5 项）
  ├─ 四层词库（步骤3 确认版 · 租户隔离）
  ├─ 行业包规则簿（禁词/合规/渠道默认/CTA/竞品类型/画像提示/scenario提示）
  └─ 用户入驻时填写的 RawInputs、竞品、核心优势

步骤4 内部处理：

  A. persona_analyze（LLM 动态生成客户画像）：
     输入 → LLM：
       1. RawInputs（客服记录/评价原文）
       2. 探针结果（AI Chat 对该品类的典型回答风格）
       3. 商家填的目标客户
       4. 行业包 persona_hint（年龄/决策因子方向提示）
     输出 → buyer_personas[]：
       {
         role: "静安寺附近的年轻白领女性",
         age_range: [25, 35],
         pain_tags: ["敏感肌反复泛红", "怕被推销", "午休时间有限"],
         decision_factors: ["口碑>资质>距离>风格标签"],
         trust_triggers: ["VISIA检测报告", "真实评价带图", "成分公开"],

     输出 → content_layout_plan[]：
       敏感肌白领 → 小红书+知乎 → 场景推荐+FAQ → 预约小程序
       抗衰熟龄 → 公众号+点评 → 深度指南+案例 → 企微咨询

  B. scenario 候选生成（LLM 从词库+画像+竞品提炼）：
     输入 → LLM：
       1. 确认后的四层词库（选型层 + 场景层）
       2. buyer_personas[]
       3. 竞品差异简报
       4. 行业包 scenario_few_shot（3-5 条示例）
     输出 → 8-10 条候选 scenario：
       "敏感肌能不能做皮肤管理"
       "静安寺附近做脸哪家不推销"
       "XX皮肤管理和YY美容院怎么选"
     → Faiss 去重（和已生成 scenario 比对）
     → 推荐给用户勾选 2-5 条
     → 用户也可手动输入

  C. 信源权重计算（内部固定 0.6 + 探针实测 0.4）：
     内部固定模型 = 实施方案 §8.3 跨平台通吃信源
       P0：搜狐号 > 网易号 > 今日头条
       P1：知乎 > 公众号 > 百度百科
       LBS：高德/点评/美团/百度地图
     探针实测模型 = 步骤2 信源地图 TOP5 域名排名
     → 混合计算每渠道权重 → 呈现「本渠道承接 N 个 scenario」

输出：方案包 Strategy Pack（一页展示 · 五区）
```

## 7. 用户核心流程

### 7.1 新用户完整链路

```
Step 1 · 舱1 懂我
  入驻填店信息 + 选主攻 AI → 点击[开始分析]
  → 诊断 agent 自动跑 5 项（探针 LLM 生成、信源地图、赛道、竞品 LLM 拆解）
  → 四层词库确认（四源汇聚+LLM提炼+用户编辑）→ 跳转方案包

Step 2 · 舱2 定方案
  方案包五区展示（画像 LLM 生成、scenario LLM 生成、渠道混合权重）
  → 用户勾选 scenario
  → 内容工厂生成（RAG 切片·步骤5）→ 内容检测（RAG 验证·步骤6）
  → 策略+草稿一次性人闸门 → [确认并发布]

Step 3 · 舱3 出结果
  发布 agent 自动发布 → 24h 后复测对比（T1 vs T0）
  → 监控 agent 持续运行（EngineAdapter 联动 target_engines）
  → 效果舱 Dashboard（四层漏斗 + 转化闭环）
  → 临界触发 → 策略草案 → 迭代
```

### 7.2 异常流程

| 场景 | 处理 |
|------|------|
| thin KB（知识库为空） | 方案包提示「先补项目+FAQ」，不硬生成空文 |
| fact_verify 不通过 | 草稿标红 + 告警类型，打回步骤5 |
| 小红书 AUTO 失败 | 自动降级 SEMI，导出标准包 |
| engine 联网 API 超时/限流 | 重试 1 次，失败 skip，不阻断 pipeline |
| 探针结果全部未提及 | 触发 gap_analyze → 策略更新草案 |
| 用户修改主攻 AI | target_engines 更新 → 下次诊断/监测自动切换 EngineAdapter |

## 9. 业务验收标准

### 9.1 MVP-A 最小路径

```
生美 1 店
  → 入驻（选主攻 AI + 填 NAP + 项目 + 竞品 + RawInputs）
  → 诊断（探针 LLM 生成 · 5项全量 · 含信源地图 · 竞品 LLM 拆解）
  → 四层词库（四源汇聚 · 租户隔离 · 用户确认编辑）
  → 方案包（persona LLM 生成 + scenario LLM 生成 + 渠道混合权重）
  → 内容工厂（scenario 模式 · RAG 切片 · 步骤5）
  → 内容检测（5 项 · 含 RAG 可检索性验证 · 步骤6）
  → 人闸门（策略+草稿合并）
  → 发布（托管页 AUTO + 小红书 SEMI）
  → 监控（24h 后 T1 vs T0 · EngineAdapter 联动）
  → 效果舱（四层漏斗 + 转化闭环）
```

### 9.2 核心验收项

| # | 验收项 | 判定标准 |
|---|--------|----------|
| AC-01 | 8 步流程跑通 | 入驻→诊断→词库→方案包→内容→检测→人闸门→发布→监控 |
| AC-02 | fact_refs 可追溯 | 参数/价格可定位到 kb_facts.id |
| AC-03 | 禁词拦截 | 行业包 forbidden_words + 广告法禁词拒发；含 AI 生成标识 |
| AC-04 | 探针 LLM 生成 | 根据品类+商圈+店名动态生成 20-30 条问句，非模板 |
| AC-05 | 四层词库租户隔离 | 不同租户词库完全不同，四源汇聚可追溯 |
| AC-06 | persona LLM 生成 | 从 RawInputs+探针实时分析，非行业包种子 |
| AC-07 | scenario LLM 生成 | 8-10 条候选，从词库+画像+竞品提炼，用户勾选 |
| AC-08 | 渠道权重混合模型 | 内部固定 0.6 + 探针实测 0.4 |
| AC-09 | RAG 切片 | 生成时切（步骤5）+ 检测时验证（步骤6） |
| AC-10 | 5 项机审 | fact_verify + 禁词 + 交叉验证 + 实体一致性 + RAG可检索性 |
| AC-11 | 人闸门合并 | 策略+草稿一次确认，approval_log 有记录 |
| AC-12 | 探针两次对比 | T0（基线）+ T1（24h 后）Δ 展示 |
| AC-13 | 主攻 AI 联动切换 | 用户改 target_engines → 监测 EngineAdapter 跟随变化 |
| AC-14 | 租户隔离 | 跨 enterprise API 403 |
| AC-15 | 行业包薄配置 | 新增品类只需配 9 项规则 + few-shot，0 管道改动 |
