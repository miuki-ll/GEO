## 1. 客户入驻引导

### 1.1 新客户上线流程

```
第 1 天 · 注册 & 开店向导
  □ 注册账号（邮箱+密码）
  □ 选择品类（生美 / 餐饮 / 维修 / 零售）
  □ 选择主攻 AI（豆包 / DeepSeek / Kimi / 文心 / 抖音AI）
  □ 填写基础信息（店名/地址/电话/营业时间）
  □ 填写服务项目（≥2 个，含价格区间 + 适用人群）
  □ 填写竞品（2-3 个店名 + 可选 URL）
  □ 填写核心优势（一句话）
  □ 粘贴 RawInputs（客服聊天/评价截图 · 可选但建议）
  □ 点击 [开始分析]

第 1 天 · 看诊断
  □ 查看 GEO 健康报告（制造焦虑话术）
  □ 查看信源地图（AI 引用了哪些平台）
  □ 查看赛道判定（空白/突围/防御）
  □ 查看竞品拆解

第 1 天 · 确认词库
  □ 浏览四层词库（认知/选型/痛点/场景）
  □ 增删改词条
  □ 确认词库

第 2 天 · 方案包 & 草稿
  □ 查看客户画像（LLM 生成）
  □ 查看竞品差异简报
  □ 勾选 2-3 个 scenario
  □ 确认方案包
  □ 审核草稿（预览/fact对照/告警处理）
  □ 策略+草稿合并确认 → 发布

第 3 天 · 发布
  □ 托管页自动发布（无需操作）
  □ 小红书/知乎 SEMI → 复制文案到对应平台
  □ 点评/美团 GUIDED → 按指引操作

第 4 天 · 看效果
  □ 24h 后查看效果舱 T0/T1 对比
  □ 确认提及率变化
```

### 1.2 客户常见问题应答

| 客户问 | 应答 |
|--------|------|
| 「为什么我的店在 AI 里搜不到？」 | 正常。90% 的本地小店都搜不到。你的店信息分散在各平台、格式不统一，AI 没法采信。我们做的事就是帮你整理成 AI 能读懂的结构。 |
| 「多久能见效？」 | 7-14 天。3 天出诊断+方案，7 天首发内容上线，14 天看第一轮效果对比。 |
| 「能保证 AI 第一个推荐我吗？」 | 不能。AI 引用是概率行为，保证排名是虚假宣传。我们能保证你的信息正确、多渠道一致、持续监测修复。 |
| 「为什么不直接自动发到所有平台？」 | 小红书/知乎等平台对 API 自动发布有风控，强行全自动会被封号。我们先用导出包（复制粘贴），后续接自动发布。 |
| 「我需要天天登录操作吗？」 | 不需要。入驻+确认后，日常只看效果舱就行。每周自动监测，有异常才提醒你。 |

## 2. 故障分级与 SLA

### 2.1 故障等级

| 级别 | 定义 | 响应时间 | 解决时间 |
|:--:|------|:--:|:--:|
| P0 | 平台不可用（API 全挂/数据库宕机） | 15 分钟 | 2 小时 |
| P1 | 核心功能不可用（不能入驻/不能发布/不能监测） | 30 分钟 | 4 小时 |
| P2 | 非核心功能异常（效果舱延迟/词库加载慢） | 2 小时 | 24 小时 |
| P3 | UI 小问题/文案错误 | 24 小时 | 下一迭代 |

### 2.2 升级路径

```
P0/P1:
  值班运维 → 技术负责人 → CTO（30分钟内未解决）
P2/P3:
  值班运维 → 产品经理 → 排入下一迭代
```

## 4. 行业包新增流程

### 4.1 新增品类步骤

```
1. 编写规则簿（~30 分钟）
   创建 agents/industry/packs/{category}/
   ├── __init__.py
   ├── pack.py       # 继承 IndustryPack · 实现 9 方法
   └── templates.py  # 数据常量

2. 注册
   agents/industry/registry.py → 添加 pack 映射

3. LLM 输出验证（1-2 周）
   - 验证探针问句质量（覆盖四层意图·自然·贴合本地）
   - 验证 scenario 候选质量（可回答·信息量够·CTA 正确）
   - 验证画像质量（人群准确·决策因子合理）
   - 验证禁词拦截（品类特有关键词/合规要求）

4. 种子数据（可选）
   编写 seed.py（测试用）

5. 上线
   无需改动任何管道代码
```

### 4.2 行业包检查清单

| # | 检查项 |
|---|--------|
| 1 | forbidden_words: 行业特有禁词完整 |
| 2 | compliance_checklist: ≥3 项 |
| 3 | channel_defaults: 5-8 个渠道 + 权重 + 发布模式 |
| 4 | competitor_types: 3-4 类 + 中文标签 |
| 5 | cta_mapping: answer_goal + landing |
| 6 | priority_verification: 一句话描述 |
| 7 | persona_hint: age_range + decision_factors + typical_needs |
| 8 | probe_few_shot: 3-5 条自然问句 |
| 9 | scenario_few_shot: 3-5 条场景问句 |

## 5. 日常运营清单

### 5.1 日

```
□ 看 Sentry 错误告警
□ 看 Celery 任务队列积压
□ 看 LLM API 调用量（防超量）
□ 回复客户咨询
```

### 5.2 周

```
□ 抽查 1 个客户的监测结果（T0/T1 对比）
□ 抽查 1 个客户的内容质量（fact_refs 溯源）
□ 检查 LLM 成本（按租户统计）
□ 周会：产品 + 技术 + 运营 同步
```

### 5.3 月

```
□ 月报：活跃客户数/新入驻/闭环天数/平均提及率
□ LLM 成本报表（按品类·按租户）
□ 数据库备份验证（restore 测试）
□ 客户满意度回访（抽样 3-5 家）
```

## 6. LLM 配额管理

### 6.1 单租户月额度

| 套餐 | LLM 调用额度/月 |
|------|:--:|
| 基础版 | 150 次 |
| 运营版 | 400 次 |
| 多店版 | 400 × 店数 |

### 6.2 熔断

```
单租户月额度耗尽 → 调用排队 → 提示升级套餐
全局月额度达 80% → 告警 → 评估扩容
```
