GEO 智能品牌平台 — 产品需求文档（技术版）

版本 V4.1 · 2026-07-04 · 读者：研发 / 架构 / 测试 · MVP 行业：生美

一、产品定义

GEO（生成式引擎优化） = 让豆包 / DeepSeek / Kimi / 文心等 AI 引用、采信企业真实品牌信息。

价值公式：内容价值 ≈ 信息增量 × 品牌信任度

  • 做：知识库零幻觉、先选 AI 测信源、按顾客场景写内容、监测迭代
  • 不做：软文铺量、保证第一、虚构品牌、刷好评

二、用户旅程（三舱 · 2 次确认）

舱用户操作
舱1 懂我开店向导提交 → 开始分析
舱2 定方案方案包确认 → 草稿审通过
舱3 出结果发布 → 效果舱 → 策略建议

人闸门：① 方案包「确认并生成」　② 草稿「通过」

铁律：无事实不发布 · 条数 = 场景数（≤5）· 监测临界只出草案、人确认后迭代

三、系统管道

录入 → 信源诊断 → 痛点/词库 → 画像/竞品 → 方案包确认 → 生成 → 机器审 → 人工审 → 发布 → 监测 → 效果舱

方案包五区块

区块内容
A 画像确认顾客画像与内容布局
B 竞品确认/编辑差异化
C 场景勾选 2～5 个顾客问题（scenario，最小生产单元）
D 渠道信源权重与各渠道承接场景数
E 展开词库（监测辅助）、知识库更新提示

四、核心规则

  • Fact 可发布：店名/地址/电话、项目、案例、FAQ
  • Signal 不可发布：粘贴的聊天/评价
  • 生成链：fact_refs → kb_fetch → LLM → fact_verify
  • 薄库门槛：≥2 个项目且 ≥3 条 FAQ，否则禁用「确认并生成」
  • 生产单元：1 场景 × 1 渠道 × 1 Skill

五、技术选型

层选型
前端Vue3 + TypeScript + Element Plus
后端Python 3.11+ / FastAPI / Pydantic v2
数据PostgreSQL / Redis / Celery / Faiss / OSS
Agentjobs + LangGraph 子图 + ReAct Harness
LLMGateway + 四引擎适配器
可观测Sentry + LangSmith + agent_traces

正文 Skill 固定链 kb_fetch → LLM → fact_verify，无 ReAct。

六、MVP-A 首发范围

项范围
诊断主攻 AI 全量；次攻可选
内容2 个场景（标准包 3 个）
发布托管页 AUTO + 1 渠道 SEMI 文案包
监测主攻 AI 一轮 + 已选场景进 Core 子集

七、关键接口

  • POST /onboarding/run
  • GET /strategy-pack/draft · POST /strategy-pack/confirm
  • GET /content-drafts · POST /content-drafts/bulk-approve
  • GET /outcomes

八、验收要点

  • 1 店全流程：向导 → 方案包 → FAQ + 1 渠道 → 托管页 → 监测 1 轮
  • 事实可追溯、禁词拦截、租户隔离、两次人审
  • SEMI 文案包可用、跨租户访问返回 403

九、版本路线

  • MVP：三舱 + 场景驱动 + kb_fetch + Core/Probe
  • V1.1：信任资产产线、ConsultLog 归因、全量场景监测
  • V2：B2B 行业包、adapt_engine 一源多形态
